# H2O Alex — оплата, Telegram і редагування товарів

## 1. Редагування товарів в адмінці (вже працює)

1. У Firebase відкрийте **Firestore → Rules**, вставте новий `firestore.rules`, натисніть **Publish**
   (додано правило для товарів — без нього зміни не збережуться).
2. Опублікуйте оновлений сайт на Vercel (див. розділ «Оновлення сайту на Vercel» нижче).
3. Зайдіть на сайт як адмін → **⚙️ Адмін → 🛍️ Товари**.
4. Вперше натисніть **«Імпортувати 19 товарів»** — стандартні товари потраплять у базу.
5. Далі: ціну можна змінити прямо у списку, 👁️ — сховати/показати товар, ✏️ — повне редагування
   (назва, опис, категорія, емодзі або фото за посиланням, «Хіт»), «+ Додати товар» — новий товар.

Фото: завантажте картинку на будь-який сервіс (наприклад imgbb.com або Google Drive з публічним доступом)
і вставте пряме посилання `https://…` у поле «Фото».

## 2. Оплата

### Що вже є
У кошику клієнт обирає спосіб оплати:
- **Готівка кур'єру** та **Картка кур'єру** — працюють одразу, спосіб видно в адмінці.
- **Переказ на картку** — вмикається, коли ви впишете у `app.js`:
  ```js
  const PAY_CARD = "5375 41XX XXXX XXXX";
  const PAY_CARD_HOLDER = "Олександр К.";
  ```
  Після замовлення клієнт побачить вікно з номером картки, сумою та кнопкою «Скопіювати».
  Підтверджувати надходження коштів доведеться вручну: змінюєте статус замовлення в адмінці.

### Онлайн-оплата карткою на сайті (наступний крок)
Для цього потрібен договір еквайрингу (ФОП/ТОВ). Найпростіші варіанти в Україні:
**Monobank Acquiring**, **LiqPay**, **WayForPay**.

Як це працює технічно: сайт → ваша серверна функція (Vercel Function) створює рахунок у банку
→ клієнт переходить на сторінку оплати → банк надсилає підтвердження (webhook) → замовлення
автоматично отримує статус «Оплачено». Секретний ключ банку **не можна** класти в `app.js` —
він лежить тільки в налаштуваннях сервера.

Коли отримаєте доступ до еквайрингу (токен/merchant id), напишіть мені — я додам кнопку
«Оплатити карткою» під вибраний банк.

## 3. Сповіщення в Telegram про нові замовлення

Потрібно ~10 хвилин. Сайт сам токен не зберігає — для цього є невелика серверна функція на Vercel
(файл `api/notify.js` вже готовий, Vercel підхоплює папку `api` автоматично).

### Крок 1. Створіть бота
1. У Telegram відкрийте **@BotFather** → `/newbot` → вигадайте назву та ім'я (закінчується на `bot`).
2. BotFather дасть **токен** (виглядає як `123456:ABC-DEF...`). Збережіть його, нікому не показуйте.

### Крок 2. Дізнайтеся свій chat id
1. Знайдіть вашого нового бота в Telegram і натисніть **Start** (напишіть йому будь-що).
2. Відкрийте в браузері (підставте свій токен):
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. У відповіді знайдіть `"chat":{"id":123456789` — це ваш **chat id**.
   (Для групи: додайте бота в групу, напишіть у ній повідомлення — id буде мінусовий, напр. `-100123…`.)

### Крок 3. Налаштуйте Vercel
1. Vercel → ваш проєкт → **Settings → Environment Variables**. Додайте три змінні (середовище: Production):
   - `TELEGRAM_BOT_TOKEN` — токен від BotFather
   - `TELEGRAM_CHAT_ID` — ваш chat id
   - `FIREBASE_API_KEY` — `apiKey` з вашого firebaseConfig (рядок `AIzaSy…`)
2. Опублікуйте сайт **разом з папкою `api`** (див. нижче). Після деплою у проєкті → **Functions** має
   з'явитися `api/notify`. Змінні набувають чинності тільки після нового деплою.

### Крок 4. Перевірка одним натиском
У `app.js` вже стоїть `NOTIFY_URL = "/api/notify"` — нічого міняти не треба.
Опублікуйте сайт (з папкою `api`), зайдіть як адмін → **⚙️ Адмін → кнопка «🔔 Тест Telegram»**.
У Telegram має прийти «🧪 Тест: Telegram підключено!». Якщо ні, сайт покаже причину:
- «Функцію не знайдено» — не завантажена папка `api`, зробіть деплой;
- «Не налаштовані змінні…» — додайте змінні й зробіть **Redeploy**;
- «Помилка перевірки входу» — неправильний `FIREBASE_API_KEY`;
- «Telegram: chat not found» — не натиснули Start у боті або неправильний chat id.

### Реальне замовлення
Зробіть тестове замовлення — у Telegram прийде повідомлення з клієнтом, телефоном, адресою,
товарами, сумою та посиланням на точку на мапі. Помилки: Vercel → проєкт → **Logs**.

> Функцію я не міг перевірити з реальним ботом у своєму середовищі (немає доступу до Telegram),
> тому перший тест зробіть самі й напишіть мені, якщо щось не спрацює.

## 4. Оновлення сайту на Vercel

- **Через GitHub (рекомендовано):** замініть файли в репозиторії новими (зі збереженням структури: `index.html`,
  `style.css`, `app.js`, папки `assets` та `api`) → Vercel сам задеплоїть за хвилину.
- **Через термінал:** у папці сайту виконайте `vercel --prod`.
- Після кожної зміни змінних середовища потрібен новий деплой (Deployments → ⋯ → Redeploy).

### ⚠️ Не забудьте домен у Firebase
Адреса на Vercel інша, ніж була на Netlify (`щось.vercel.app`). Додайте її, інакше вхід через Google
покаже `auth/unauthorized-domain`:
**Firebase → Security → Authentication → Settings → Authorized domains → Add domain**
(без `https://`). Якщо підключите власний домен, додайте і його.

Також якщо відкриваєте посилання-превʼю (`…-git-…vercel.app`) — це інша адреса, її теж треба додавати.
Працюйте з головною адресою проєкту (Production).

## 5. Вхід через Google на телефоні

**Проблема:** на телефоні вхід «крутився» і повертав на сторінку без акаунта. Причина — сайт на Vercel, а
вхід Firebase працює з іншого домену (`…firebaseapp.com`); телефонні браузери блокують таку зв'язку.

**Рішення (вже в коді):** на телефонах вхід іде не у вікні, а переходом (redirect) і проксується через
ваш власний домен (файл `vercel.json`). Щоб це запрацювало, зробіть **один раз**:

1. Опублікуйте сайт на Vercel **з файлом `vercel.json`** (він лежить у корені, поруч з `index.html`).
2. Відкрийте https://console.cloud.google.com → угорі виберіть проєкт `shop-water-8e150`.
3. Меню **APIs & Services → Credentials**.
4. У розділі **OAuth 2.0 Client IDs** відкрийте **Web client (auto created by Google Service)**.
5. У полі **Authorized redirect URIs** натисніть **+ ADD URI** і вставте
   `https://ВАША-АДРЕСА.vercel.app/__/auth/handler`
   (підставте точну адресу сайту; якщо підключите власний домен — додайте і для нього).
6. Натисніть **Save** (зміни можуть діяти до кількох хвилин).

Перевірка: відкрийте сайт у Chrome/Safari на телефоні → «Профіль» → «Увійти через Google».

Якщо Google показує `redirect_uri_mismatch` — адреса в кроці 5 не збігається з адресою сайту.
Якщо вхід тільки з Telegram/Instagram не працює — це обмеження Google для вбудованих браузерів,
сайт сам підкаже відкрити його в Chrome або Safari.
Вимкнути цей режим можна, поставивши `MOBILE_REDIRECT_LOGIN = false` у `app.js`.

## 6. Фото товарів

У вікні редагування товару: **«📷 Завантажити фото»** — виберіть файл з телефону чи комп'ютера.
Фото автоматично стискається (до ~640 px, ≈100 КБ) і зберігається разом із товаром у базі —
додаткових сервісів і оплати не потрібно. Також можна вставити посилання `https://…`.
Порада: 1 товар = 1 невелике фото. Для магазину на кілька десятків товарів цього більш ніж досить;
для сотень фото краще винести в окреме сховище (напишіть мені — допоможу).

## 7. Вибір адреси на мапі

У кошику та в профілі біля поля адреси є кнопка **«📍 На мапі»**. Клієнт рухає мапу (крапля по центру
показує точку), адреса визначається автоматично; можна скористатися пошуком або кнопкою «🎯 Я тут».
Після підтвердження адреса потрапляє в поле (клієнт може дописати під'їзд чи квартиру), а координати
зберігаються в замовленні. В адмінці біля адреси з'являється посилання **«🗺️ Відкрити на мапі»**,
а в Telegram-сповіщенні — посилання на точку.

У вікні мапи зверху є перемикач **«🏙️ Олександрія» / «🌾 Олександрійський район»**. Для кожної зони своя
стартова точка, свої межі мапи та пошук лише в цих межах (у районі шукаються й села). Налаштування у верху
`app.js` в об'єкті `ZONES`: `center`, `zoom`, `bounds` (координати орієнтовні — поправте за потреби;
можна змінити назви або додати ще зони). Мапа — OpenStreetMap (безкоштовно, ключі не потрібні); пошук і визначення
адреси — Nominatim. Це підходить для невеликого магазину; для великого трафіку краще платний сервіс
(Google Maps, Mapbox) — напишіть мені, підключу.

## 8. Помилка `redirect_uri_mismatch` під час входу з телефона

Це означає, що в Google ще не дозволено адресу повернення. Виправлення (один раз):
1. https://console.cloud.google.com → проєкт `shop-water-8e150`.
2. **APIs & Services → Credentials → OAuth 2.0 Client IDs → Web client (auto created by Google Service)**.
3. **Authorized redirect URIs → + ADD URI** → `https://h2oalex.vercel.app/__/auth/handler`
   (якщо адреса вашого сайту інша — підставте її). Додайте також `https://h2oalex.vercel.app` у
   **Authorized JavaScript origins**.
4. **Save** і зачекайте 3–5 хвилин (інколи довше).

## 9. Захист від фейкових замовлень

Що вже працює в коді:
- Замовлення створюється зі статусом **«Очікує підтвердження»**. Менеджер дзвонить клієнту, і лише після цього ставить **«Підтверджено»** (далі «В обробці» → «Виконано»).
- Клієнт має поставити галочку «Підтверджую, що замовлення справжнє».
- Мінімальна сума `MIN_ORDER`, ліміт замовлень, що чекають підтвердження, `MAX_PENDING`, пауза між замовленнями `ORDER_COOLDOWN_SEC` (усе у верху `app.js`).
- Приховане поле-приманка для ботів, перевірка телефону й даних замовлення в `firestore.rules`.
- У Telegram приходить «Зателефонуйте клієнту для підтвердження» і позначка «🆕 Новий клієнт».
- В адмінці біля клієнта є кнопка **«🚫 Заблокувати»**: заблокований не зможе створювати замовлення.

**Обов'язково:** опублікуйте новий `firestore.rules` (Firestore → Rules → Publish), інакше блокування й перевірки на сервері не діятимуть.
Ліміти в `app.js` перевіряються у браузері, тож рішуче налаштована людина може їх обійти. Основний захист — дзвінок менеджера й блокування.
Надійніше за все — **передоплата карткою** (розділ 10): тоді фейки втрачають сенс.

## 10. Онлайн-оплата LiqPay (вже підключена в коді)

У кошику з'являється спосіб **«Оплата карткою онлайн (LiqPay)»**. Після замовлення клієнт переходить на сторінку LiqPay;
коли банк підтвердить оплату, замовлення в адмінці отримує позначку **💳 Оплачено**, а в Telegram приходить повідомлення.
Якщо клієнт не оплатив, у «Мої замовлення» є кнопка «Оплатити». Суму сервер бере з бази, змінити її в браузері неможливо.

Налаштування (один раз):
1. liqpay.ua → ваш магазин → скопіюйте **Public key** і **Private key**.
2. Firebase → ⚙️ Project settings → **Service accounts → Generate new private key**. Завантажиться JSON-файл. Відкрийте його й скопіюйте весь вміст.
3. Vercel → Settings → Environment Variables, додайте:
   - `LIQPAY_PUBLIC_KEY` — Public key;
   - `LIQPAY_PRIVATE_KEY` — Private key;
   - `FIREBASE_SERVICE_ACCOUNT` — увесь вміст JSON-файлу (одним значенням);
   - `FIREBASE_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — вже є з розділу 3.
4. Завантажте на GitHub нові файли: `package.json`, `api/liqpay.js`, `api/liqpay-callback.js` (Vercel сам встановить `firebase-admin`), потім **Redeploy**.
5. Опублікуйте новий `firestore.rules`.
6. Перевірка: зробіть замовлення з оплатою LiqPay на мінімальну суму (або в режимі sandbox у кабінеті LiqPay).
Якщо LiqPay вам поки не потрібен, поставте `LIQPAY_ENABLED = false` у `app.js`.
Ключі й JSON сервісного акаунта **ніколи** не кладіть у код чи на GitHub: тільки у змінні Vercel.

## 11. Як швидко міняти файли на GitHub
- **У браузері:** відкрийте репозиторій → потрібну папку → **Add file → Upload files** → перетягніть нові файли (з тими самими іменами; файли з папки `api` завантажуйте всередині `api`) → **Commit changes**. Старі файли з такими самими іменами замінюються. Vercel сам оновить сайт за ~1 хв.
- **Через термінал:** розпакуйте архів у папку репозиторію, потім `git add . && git commit -m "update" && git push`.
- Після оновлення на телефоні й комп'ютері натисніть Ctrl+F5.
